## Design Specificity Verdict

**LLM assessment:** Interface feels partially authored for the hospital context. The "STARKES" accreditation badge and "RS Bhayangkara Nganjuk" branding establish product identity in the header. The PDF viewer itself, however, is a generic third-party shell with zero customization toward the clinical tone — no brand color passed to the viewer, no custom toolbar skin, no domain-specific messaging. The page could serve any organization's document viewer with a one-line text change. Category-interchangeable at the viewer layer.

**Deterministic scan:** 0 violations. Exit code 0. Detector found no anti-pattern matches in `page.js` or `PDFViewerComponent.jsx`.

**Static analysis (B):** Detector clean, but manual review surfaced four code-quality issues not caught by pattern rules: dead import (`Bookmark` imported, never used), `defaultLayoutPlugin()` instantiated outside `useMemo` (recreates on every re-render), a forced viewer remount caused by `key` depending on `initialPage` state set inside `useEffect`, and an unscoped localStorage key that cannot differentiate document versions.

## Overall Impression

A solid functional shell that does its job — opens the accreditation PDF, remembers your page, and recovers gracefully from errors. But it ships design system violations that make it feel like a different product from the rest of the dashboard, and two reactivity bugs that degrade the PDF reading experience on first load. The single biggest opportunity: make the viewer feel like it belongs to this hospital's brand rather than a dropped-in PDF library demo.

## What's Working

1. **Last-page persistence via localStorage** — `sdm_akreditasi_last_page` restores reading position on return. Rare, thoughtful touch that respects user time in a document that's 35 pages long.
2. **Error state with download fallback** — When the PDF fails to load, the user gets two concrete exits (retry + direct download) rather than a dead end. No user gets stuck.
3. **Progress bar with page counter** — Spatial awareness during a long document read reduces fatigue. The `aria-valuenow` implementation is correct.

## Priority Issues

**[P0] Brand color violation — `sky-600` used instead of system cyan**
- **What:** `page.js` uses `sky-600`, `sky-50`, `sky-100`, `sky-700` throughout. Design system mandates Brand Cyan `#0891B2` (`cyan-600` in Tailwind), Pale Cyan `#F0F9FF` for low-emphasis surfaces.
- **Why it matters:** Every accented element — the progress bar, the badge border, the header icon — reads as a different hue from every other dashboard page. Breaks visual cohesion for any user navigating between sections.
- **Fix:** Replace `sky-*` utilities with `cyan-*` equivalents across `page.js`. `sky-600` → `cyan-600`, `sky-50` → `cyan-50`, etc. Confirm `#0891B2` maps to `cyan-600` in the project's Tailwind config.
- **Suggested command:** `$impeccable polish`

**[P1] Card radius violation — `rounded-2xl` (16px) instead of system 12px**
- **What:** Card and container elements use `rounded-2xl`. Design system specifies 12px (`rounded-xl`) for cards and dialogs.
- **Why it matters:** Corner radius is one of the most visible consistency signals. A page that rounds more aggressively than every other card looks like a component imported from a different product.
- **Fix:** Replace `rounded-2xl` with `rounded-xl` in `page.js`.
- **Suggested command:** `$impeccable polish`

**[P1] `defaultLayoutPlugin()` not memoized — recreates on every render**
- **What:** `PDFViewerComponent.jsx` calls `defaultLayoutPlugin()` in the component body without `useMemo`. Every parent re-render recreates the plugin instance.
- **Why it matters:** Plugin recreation can reset sidebar state (outline, thumbnails) mid-session and causes unnecessary work on the PDF renderer. Users lose sidebar position silently.
- **Fix:** Wrap in `useMemo(() => defaultLayoutPlugin(), [])` or move instantiation outside the component.
- **Suggested command:** `$impeccable harden`

**[P1] viewer remount on first load — `key` depends on `initialPage` state set in `useEffect`**
- **What:** `PDFViewerComponent` receives `key={\`${viewerKey}-${initialPage}\`}`. `initialPage` is set inside a `useEffect` that reads from localStorage after mount. This means the viewer renders once with `initialPage=0`, then unmounts and remounts with the restored page — a visible flash/reload on every page visit.
- **Why it matters:** Users with a saved page see the document load twice: once at page 1, then jump to their saved page. Creates a jarring experience for the exact feature meant to delight (page persistence).
- **Fix:** Read localStorage synchronously during initial state: `const [initialPage, setInitialPage] = useState(() => parseInt(localStorage.getItem(STORAGE_KEY) || '0', 10))`. Remove the `useEffect` that sets `initialPage`. The `key` can then be just `viewerKey` (or removed entirely if not needed for reset logic).
- **Suggested command:** `$impeccable harden`

**[P2] Typography: no explicit font classes on headings**
- **What:** `CardTitle` and section headings lack `font-heading` or explicit Figtree targeting. Body copy lacks Noto Sans class. Relies entirely on CSS inheritance from layout.
- **Why it matters:** If the global CSS changes or a component is reused elsewhere, font identity silently breaks. Low risk now, fragile long-term.
- **Fix:** Add `font-heading` (or `font-figtree`) to `CardTitle`. Add `font-body` to descriptive paragraphs.
- **Suggested command:** `$impeccable typeset`

## Persona Red Flags

**Alex (Power User):** No keyboard shortcut panel visible for the PDF viewer. The floating STARKES badge (`fixed bottom-4 right-4`) overlaps the PDF viewer's own bottom-right control cluster (zoom, scroll mode) in default layout — Alex reaches for zoom and hits the badge instead. No page-jump input field; must click through page-by-page controls.

**Sam (Accessibility-Dependent):** The STARKES floating badge uses `text-[10px]` — below the 12px WCAG minimum for small text and well below the 14px body floor. The badge has no ARIA label; a screen reader announces only its text content, with no role or context. Positive: `role="progressbar"`, `aria-live="polite"` on loading, and `role="alert"` on error are all correctly implemented — Sam can navigate the main flow.

**Riley (Stress Tester):** localStorage key `sdm_akreditasi_last_page` is not scoped to document version or path. If the PDF is updated server-side but the client cache points to page 34 of the old document, the restored page may be out of bounds — the viewer will silently show the last available page with no explanation.

## Minor Observations

- `Bookmark` imported from `lucide-react` in `page.js` line 7 — never used in markup. Dead import, remove.
- Button height `h-7 sm:h-9` — system specifies 36–40px default; 28px (`h-7`) is below the 44pt touch target floor for mobile.
- Hospital name "RS Bhayangkara Nganjuk" hardcoded in two places. Should reference a config constant or environment variable.
- `PDF_DOCUMENT_PATH = "/documents/akreditasi.pdf"` hardcoded. Fine for a single-document viewer, but a comment noting the intentional limitation would prevent future confusion.
